# 明日检查入口

正式工程目录为`/home/ayanami/job-search/career-assistant`。已配置的私有文件不纳入交付；不需要在聊天中提供密钥或Cookie。

## 本地启动

```sh
cd /home/ayanami/job-search/career-assistant
pnpm install --frozen-lockfile
pnpm db:generate
# 使用自带本地数据库时先启动；已有可用数据库则无需此命令。
docker compose -p career-assistant-dev up -d postgres
pnpm db:migrate
pnpm build
pnpm dev
```

`pnpm dev`同时启动Web、API、Agent和Worker，Ctrl+C一起停止。默认Web地址为`http://127.0.0.1:5173`，以本地配置为准。API与Worker不读取模型密钥，Agent启动器继续兼容已配置的`tools/verification/.env.verification`。来源网络默认关闭；不要为演示擅自重置历史请求预算。启动与健康检查不调用模型，但发送咨询或提交简历解析会使用实际配置的模型。

业务库按本地`.env`选择，首次启动需执行全部迁移。测试使用另外创建的隔离PG，不会向业务库插入虚构用户或岗位；没有采集数据时岗位页显示空列表。已保存的5条真实岗位取样与完整性限制见`docs/ingestion/README.md`和源数据导出，不能当成当前全站覆盖。

## 推荐检查路径

1. 注册、登录、刷新页面，确认会话保留；无邮箱手机号，无密码找回。
2. 在“我的画像”手填教育/实习/正式工作，保存草稿，再明确确认；未知留空，检查日期精度与版本冲突提示。
3. 在“求职咨询”的输入区点击“上传简历 / 管理简历”，上传TXT/PDF/DOCX或粘贴，查看排队、文字提取、模型结构化和草稿；查看页段原文，点击“核对画像草稿”纠正后明确确认，再点击“返回求职咨询”。旧`/resumes`地址自动跳转并展开简历区；展开/收起不清空当前问题和所选会话。扫描件、加密和超限应明确失败。
4. 在“求职咨询”新建咨询，连续提问求职方向、简历建议、面试准备；取消、刷新与失败后显式重试。模型不可用应显示失败，不能用固定答案装作成功。
5. 有岗位数据时浏览校招和社招、筛选、查看原文与核验时间，使用正式画像核验。缺失或过期显示待核验，符合条件的应届生不会因为社招标签被直接排除。
6. 收藏岗位、加入准备投递，手动调整状态/日期/备注，查看历史，再删除；助手不会自动报名。
7. “隐私与数据”分别检查清空画像、清空个人求职数据和删除账号；原始文件清理与访问撤销分开显示，账号删除要求当前密码并让所有设备退出。
8. 查看“数据与可信说明”的实际收录、完整核验、新鲜度和积压；不要把旧取样时间当成实时抓取。

## 验证与部署

`pnpm check`执行完整质量检查；真实PG和Playwright需要Docker及浏览器运行库。`pnpm test:deployment`只对专门命名的隔离Compose项目进行本地生产容器、HTTPS、重启、备份恢复验证，要求预先构建`career-assistant:batch-check`及`career-assistant-web:batch-check`两个镜像。它不使用用户数据库、不调用模型或来源，并清理自己的卷。

公网部署、远端推送、额外真实模型/来源验证及至少7天在线安排均未执行，需后续明确配置和授权。部署步骤、故障和回退见[部署手册](deployment.md)。
