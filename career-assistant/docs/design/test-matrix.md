总体设计版本0.1已随第二步验收；具体模块仍单独确认。**AUTH-01—06及HEALTH-01—04已执行，其他业务接口仍待实现；第三步VERIFY结果见[验证记录](../verification/README.md)。**此矩阵不是全部业务测试通过报告，具体测试随获批模块实现。

## 测试层和公共断言

每个下表操作 ID 对应独立的测试分组，不允许仅测试路由存在。需要对照实际路由注册、MCP tools/list 和 CLI 注册表检查遗漏。

- BASE-P：成功输出契约、缺失/非法输入、错误映射、无敏感信息、限流适用情况。
- BASE-U：BASE-P + 未认证401、失效会话、跨用户私有资源404、写入的 Origin/CSRF 拒绝和失败无业务副作用。
- BASE-S：BASE-P + 服务凭据、运行范围、过期授权、User撤销状态、模型参数不能伪造身份。
- BASE-O：参数校验、受保护本地执行、错误退出、输出契约、无凭据泄漏。
- 写入另测事务回滚；K 操作测重复同内容、同键异内容、并发相同键，结果和副作用各验证一次。
- DTO 测类型、长度、必填、默认和关联校验；领域测状态与不变量；Service 测编排及异常；Repository 用真实 PostgreSQL 测映射、唯一约束、CAS、锁、回滚及并发连接。
- 验证失败需要断言数据没有错误变化，不能只断言 HTTP 状态码。

## 测试数据和执行记录规范

- 虚构学生：本科预计毕业、已毕业硕士、专业未知、无正式经验但有实习、生日边界、重叠工作经历、证书未知；均标测试数据。
- 虚构岗位夹具：社招经验不限、经验要求三年、AND/OR混合、缺截止、当天无时刻、明确关闭、公告冲突、文档变化；不进入生产岗位库冒充采集结果。
- 时间通过时钟注入，测试跨日、时区、48小时边界和生日，不依赖机器当前时间。
- 并发通过两个真实连接及同步屏障启动，在最终 DB 状态和受影响行数上断言；不以 Promise.all 本身证明真正发生竞争。
- 数据库测试使用隔离测试库，不对生产库执行清理。各 E2E 有独立用户、来源命名空间和幂等标识，结束清理。
- CI常规运行可控替身，不消耗真实模型或高频访问来源。真实外部 smoke 验证在授权配置下单列调用时间、模型、来源、成功范围和限制。
- 测试报告记录命令、提交/文档版本、环境、通过/失败/未运行及原因。执行事实以第三步记录及后续模块报告为准，不能将本矩阵的设计行误计为所有业务用例已通过。
