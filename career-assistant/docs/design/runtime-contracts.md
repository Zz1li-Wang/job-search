# 批量实现后的运行契约

本文件补充第二步接口提案，描述当前本地实现。用户“将后面任务全部写完吧，明天我来检查”授权连续实现；完成实现仍待用户检查，不能记为用户已验收。

真实入口和可执行测试以`tests/interface-registry.json`（60个HTTP操作）及`tests/mcp-registry.json`（8个工具）为准。字段、约束和描述在`packages/contracts/src/`，运行时由Zod校验。所有浏览器接口前缀`/api/v1`，使用Cookie、写操作Origin和CSRF校验；Agent入口及MCP要求服务Bearer和受限运行授权，模型不能指定用户。

## 相对提案的具体化

前端首版使用React/Vite/Router、轻量CSS及原生可访问表单完成界面，没有添加仅形式上的Tailwind/shadcn依赖；这是本轮待集中检查的实现适配。Agent与业务服务独立、Monorepo和领域分层保持原方案。

- 岗位使用带筛选摘要、快照时间和签名的游标分页。工作台其余列表首版返回有界数组：会话与简历最多100条、收藏与投递/历史最多500条、消息读取最近1000条；当前不提供这些列表的翻页交互。这是首版容量限制，不能宣传为不限量历史查询。模型另只读取最近12条及更早原文摘录，并限制输入预算；摘录不写入正式画像。
- 新会话支持可选`Idempotency-Key`，同键同标题返回已有会话，改内容409；不提供键表示新建一次会话。消息以会话+`clientMessageId`去重。原失败运行的重试以原runId自然去重，绑定所见版本，同一请求返回首次子运行，不再次收费调用。
- 会话删除在同一事务取消运行、清除消息/运行事件并保留删除屏障，返回204；重复删除仍204，删除后消息、运行和SSE不可读。无需文件清理任务。
- SSE支持`after`及`Last-Event-ID`；服务端只发布已提交事件，超过单批1000条继续回放至最后序号。HTTP连接定时结束后客户端可按最后ID重连，重连不新建模型运行。
- 简历上传/粘贴以用户内文件摘要去重，稳定操作键检测请求内容冲突；预存前先登记一小时后可回收的清理凭据，正式引用与解除回收同事务。崩溃留下的孤立文件仍有凭据可清理。
- `/resumes/:id/parse`返回带taskId、状态和draftId的ResumeDto，而非来源采集TaskDto。简历任务状态从简历读取；`/tasks/:id`保留公共岗位刷新任务语义。显式重新解析必须携带所见`expectedTaskId`，过时尝试不能触发第三次调用。Agent对同一提取运行的在途请求合并，终结后返回冲突，需读取后端状态；不缓存终结画像正文供重放。
- 简历删除返回202 DeletionDto，scope为resume。原文及来源草稿立即不可访问，已有独立正式画像保留。文件物理清理失败保留补偿任务；`/deletions/:id`可查询。未知或他人简历404，本人重复删除复用请求ID。
- 草稿新建使用操作键，编辑通过`expectedDraftVersion`作CAS；重复提交旧草稿版本返回409并要求重新载入。确认绑定草稿和正式画像版本，重复确认返回首次正式快照及isCurrent；删除源草稿后不恢复该快照接口。
- 收藏按用户+岗位自然键重复成功；删除204。投递创建按同一自然键复用，不重置状态；修改的幂等记录绑定不可变历史行，无变化也保留首次响应；并发旧版本409，删除后旧创建键不能恢复记录。
- 个人资料清空增加personalDataEpoch，账号删除再增加authEpoch并撤销所有会话。HTTP认证上下文携带认证时的个人资料版本，删除前已认证但迟到的上传/写入返回409 AUTH_CONTEXT_STALE，保留登录；MCP每次在业务事务内复查运行与删除版本。文件存储I/O、模型和HTTP均在业务事务之外。
- 公开资格卡片在事件落库时再查实际资格记录和依赖，失效降为待核验；模型不能把后端结论改成相反结论。前端卡片读取当前资格有效性；引用须对应实际资源、正文版本和获取观察。

## 工具清单

| 工具                   | 作用与输入                                | 输出及失败/重复行为                                              |
| ---------------------- | ----------------------------------------- | ---------------------------------------------------------------- |
| get_profile            | 无身份参数，读取本人正式画像              | 无画像为null/版本0；只读可重复                                   |
| search_jobs            | 关键词、地点、类型、学历、游标等JobQuery  | 候选岗位，不代表可报名；非法游标拒绝                             |
| get_job_evidence       | 已收录jobId                               | 原文/公告/版本/观察/未访问入口；不存在404                        |
| evaluate_eligibility   | 岗位/画像/核验/证据所见版本和operationKey | 三态结果及依据；过期409，同键同内容复用                          |
| request_job_refresh    | jobId和operationKey                       | 异步任务；合并活跃任务，遵守来源冷却及限流，不伪称刷新成功       |
| get_task_status        | taskId                                    | 仅本人请求关联任务；越权/不存在均不返回任务                      |
| read_resume            | resumeId、expectedVersion                 | 本人页段原文；解析授权仅可读指定文件，未就绪409，删除/越权不可读 |
| propose_profile_update | content、baseProfileVersion、operationKey | 仅创建待确认草稿；不修改正式画像，同键不同内容409                |

每个运行最多25次工具调用，包含失败调用和自动读取正式画像；Agent推理120秒，后端授权租约150秒，模型超时结果未知时不自动重复收费。工具参数使用严格DTO拒绝额外身份字段。网页和简历均作为不可信资料，不改变白名单或授权。普通求职建议与特定公告事实分开表达；字段校验检验引用、规范值和结构，不替代用户核对文意。

## 分层、并发和测试证据

HTTP/MCP→DTO→应用Service→领域Entity→Repository→Prisma，ORM和SQL封闭于基础设施。User锁先于所属会话/运行/画像/投递记录；来源依赖沿用流锁与资源锁。网络在事务提交后进行，回调、草稿、历史和可靠任务采用短事务条件写入。原文删除、迟到请求、重复计费、事件乱序和并发确认均有真实PG集成用例。

模块浏览器E2E覆盖账号、岗位资格、对话、简历确认、手填画像、收藏投递、隐私删除，并有移动端从简历到咨询、核验、进度及清空的完整路径。模型使用本地HTTP替身，MCP使用官方SDK实际传输，数据库是真实隔离PostgreSQL。第三步真实模型5次、真实来源累计53次为历史证据；本轮未增加真实调用，不把替身当成DeepSeek实测。

## 本地检查后的入口调整

用户在统一入口方案0.1后指示“先执行改动”，本轮前端将简历交互并入`/chat`：输入区展开/收起`ResumePanel`，仅在已登录且展开时挂载和轮询；展开状态使用`resumes=open`查询参数，旧`/resumes`以replace跳转到相同入口。收起不卸载ChatPage，保留所选会话和未发送问题。原画像草稿在`/profile?draft=...`明确确认，提供固定咨询返回链接；不将简历原文自动注入聊天或自动发送消息。本次没有HTTP、MCP、数据库、权限、计费或事务契约变化。后续按用户“允许多次检查，直到修复”授权完成简历格式与依据修复，见[修复记录](resume-parse-fix.md)。

## 简历输出与失败分类修复

日期value的规范格式pattern现能进入模型JSON Schema，保留原精度/日历关联校验。已知日期对象证据可规范到/value，明确叶子引用优先，日期值不被改写；经历说明使用经定位核对的原文引用，拒绝虚构引用。学历取得和毕业性质不得按日期推断，无明确依据使用unknown。内部提取失败使用现有ErrorResponse信封和受限既有错误码返回502；认证/非法输入继续403/400，未知异常仍安全过滤。Worker只信任已验证信封及白名单，保留MODEL_OUTPUT_INVALID等业务分类；未知/畸形响应仍为结果未知，不自动收费重试。没有数据库迁移、正式画像自动确认或原文校验放宽。

## 咨询工具预算修复

按用户要求提高至25次，数据库CHECK通过新增迁移同步，包含自动画像读取和失败调用。达到上限关闭工具并仅根据已获证据完成回答；同批未执行调用明确返回未执行。上下文超限改为MODEL_CONTEXT_EXCEEDED，页面按错误码解释，Agent日志记录安全错误码和运行ID。见[修复方案](chat-budget-fix.md)。
